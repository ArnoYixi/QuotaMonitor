# 验收清单

## 0.1.5 文字、排版、菜单与锁定验收

- 纯色背景上主界面没有底色、边框、标题、设置按钮或刷新时间。
- Windows 复杂壁纸、图标或棋盘格背景上自动增加半透明圆角衬底，黑白文字跟随背景明暗；移回纯色后衬底淡出。
- 衬底强度最高约 58%，不得出现实心大面板；保持复杂背景数秒，不得因采样自身衬底而来回闪烁。账号分别取样，横条与圆环均适用。
- 黑白文字无描边；灰色背景截图中不能出现外围黑色笔画。
- 横条和圆环无黑色外描边，仍保留额度颜色和未使用部分的轨道。
- 名称后只显示正数卡片和积分，例如 `*3重置卡 *200积分`；零、未知、无效数值省略，重复额度桶不重复累计。
- 积分在悬浮窗和详情页统一向上取整、不保留小数；`0.0004` 显示为 `1`，`1.2` 显示为 `2`，`200.000` 仍显示 `200`，不修改原始余额。
- 衬底随文字和图形尺寸计算，左右各 8、上下各 6 个逻辑像素；底部无重置按钮预留空白。长名称截断时优先保留卡片和积分。
- 按住账号文字或额度进度条拖动，窗口随鼠标移动。
- 右键固定四项，顺序为「使用重置卡」「锁定悬浮」「打开菜单」「退出」。非耗尽账号的重置项禁用；耗尽且有完整可用卡时可执行。
- 选择打开菜单后显示设置；按 Esc / 返回立即收起。设置内没有解锁开关。
- 锁定后悬浮内容仍可见，但文字、进度条、衬底上的左右键都传给下方应用，不能拖动或弹出悬浮菜单。
- Windows CI 在真实 EXE 下方放独立进程的 WinForms 按钮，检查锁定前后的实际点击计数，不仅检查窗口样式。
- 仅托盘右键「解锁悬浮」恢复鼠标交互；托盘左键保持锁定。重启恢复锁定和穿透，锁定时仍可通过托盘退出。
- 连续锁定、解锁立即生效，不操作显示/隐藏；隐藏时刷新和解锁保持隐藏。后台事件与设置保存不依赖界面绘制。
- 托盘菜单只在右键松开后弹出。锁定时依次验证隐藏、显示、打开菜单、返回悬浮窗、刷新，以及锁定且隐藏时退出；菜单关闭或取消后可再次打开。
- 横条、圆环只在复杂背景上有衬底。
- Windows CI 启动真实 EXE，识别真实浮窗而非线程辅助窗口，实测拖动与右键展开。
- 移到顶部、底部时账号横向并排；移到左右边缘时恢复纵排，窗口调整大小后不越过当前屏幕工作区。
- 已经横排后再次拖出顶部，松手后整个窗口回到工作区，不能因为尺寸没变而漏掉校正；浅越界、深越界和顶部左右角均验收。
- 拖动期间不抢位置；松手才校正。启动时恢复的越界位置、其他三个方向的越界也会校正。
- 将悬浮窗背后的背景从黑改白，检查同一批字形像素由白变黑；验证窗口没有任务栏标签。
- 实际打开原生托盘菜单，依次执行隐藏、显示、设置、隐藏后打开设置、返回悬浮界面、退出。

## 先检查程序本身

1. Windows x64 解压发布包，直接运行 `QuotaMonitori.exe`。无需安装语言运行环境。首次启动完成官方组件解压后，应看到添加账号界面。
2. 运行 `Demo.bat`，看到明确的「演示」标识和三个账号，剩余额度分别为 76%、22%、0%。
3. 切换横条 / 圆环；检查高额度绿色、低额度橙色、0% 红色，以及第一账号的卡片与积分后缀、第二账号无后缀。检查内边距和无描边文字。
4. 右键第三个账号选择「使用重置卡」，卡片数量从 3 变为 2；进入详情检查最早到期卡已被消耗，长期卡还在。再次模拟耗尽，继续验证排序。再验证锁定穿透、托盘解锁和重启恢复。
5. 改为 10 秒刷新；关闭并重启，检查视图与设置保存。托盘恢复 / 退出可用；无托盘服务时关闭即退出。

## 再验收真实账号

1. 正常启动程序，添加账号，选择浏览器或设备码登录，在 OpenAI 官方页面完成验证。
2. 添加第二个账号，在浏览器中确认账号身份。分别设置别名，对照各自 Codex 官方额度页面。
3. 切换 10 / 30 秒间隔，检查更新时间；暂停一个账号后，另一个继续更新。
4. 断网后观察错误和过期状态，恢复网络后检查自动重试。未知卡片数量应显示未知，不显示为 0。
5. 只有在确实想消耗一张卡时，才在已耗尽账号点击「使用 1 张」。对照卡片到期顺序和服务端结果。若官方没有提供完整卡片列表或账号 ID，程序应给出原因并暂停使用。
6. 若出现「核对重置」，先核对同一次操作，避免删数据或移除账号；程序保留同一操作编号跨重启核对。
7. 退出登录并移除账号后，该账号不再轮询；其他账号保持登录。没有待核对操作时才能移除。

## 自动化测试覆盖

`cargo test --all-targets --locked`：

- 最早到期、同日稳定排序、无期限最后、过期卡排除。
- 明细缺失、重复卡 ID、明细数不匹配、未知类型阻止消费。
- 耗尽判断、显示取整、颜色连续性、数据过期。
- 原子设置、无效账号目录、重置日志损坏、官方登录域名校验。
- 子进程 JSON-RPC 消息交错、多个账号独立目录。
- 服务端已扣卡但响应丢失，客户端重启后复用原操作编号和原卡，实际仅扣一次。
- 待核对操作允许重新登录，但不允许重放到另一个账号。
- 卡片和积分后缀的零值、未知值、无效余额、小数、无限积分与重复桶处理。
- 用内嵌中文字体实际布局横条和圆环，检查每段文字仅绘制一次、正数后缀显示、文字留在左右 8 / 上下 6 的内边距内，以及进度条底部恰好保留 6 个逻辑像素。
- 不执行 UI 绘制时，验证托盘控制、隐藏刷新、后台数据接收和设置落盘；原生 Windows 输入样式验证连续锁定/解锁与隐藏状态。

Windows 桌面与 OpenGL 可用时另运行：

```powershell
cargo test --locked --bin QuotaMonitori desktop::tests::event_loop_unlocks_and_exits_when_rendering_is_disabled -- --ignored --exact
```

该回归启动真实 eframe 窗口，暂停绘制后验证连续锁定、解锁、隐藏、打开设置；断言绘制次数不变，并在恢复绘制后确认旧锁定状态不会被重新应用，最后验证隐藏退出和设置保存。

真实账号登录和实际消费无法由无凭据测试替代。演示模式不会证明某个订阅支持重置卡。
